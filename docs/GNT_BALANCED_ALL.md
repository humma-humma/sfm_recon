# All-four balanced splat rollout

Review: http://localhost:8088/gnt-balanced-all.html

This run applies the tested 90/10 supervision policy to box, boot and milk, and exports the already trained scene model. It is an experimental candidate and does not change selected presentation models. Full videos use native splat renders at 960 × 540 and 30 fps; no motion-compensated interpolation is used. These are not dense GNT videos and are expected to lose detail compared with GNT.

Each object reuses its adapted 6k GNT checkpoint and generates 60 sparse route frames plus 180 frames over one six-second section. The section is chosen before rendering by maximum summed camera rotation over an integer-start six-second route window. Routes follow captured camera order with linear centers and SLERP rotations, without an invented closing orbit. Sparse route playback is 32 seconds, with the final pose held for the last fraction of a second. Source photographs at interval eight are excluded from teacher source RGB. Existing box frames are reused after hash verification.

Dense frames within 0.1 ms of sparse training times are excluded from the novel split. The remaining views alternate between added training targets and withheld evaluation targets. Objects first receive a fresh 10k-step teacher-only Gaussian fit. Three matched 2k continuations start from that checkpoint and optimizer state: sparse-only control, uniform dense and balanced 90/10. Refinement is disabled in continuations. Balanced uses 1,800 sparse batches and 200 added batches with shuffled coverage. No original photograph RGB enters training; interval-eight photographs are evaluated separately. Camera estimation and seed geometry predate all splits.

The scene reuses its completed control, uniform dense and balanced checkpoints. Its dense supervision still covers the previously tested turn only. This run does not claim uniform quality improvement over its full 146.5-second route. Native normalization/camera matrices, image dimensions, source hashes, split exclusions, finite tensors, optimizer bindings, fixed continuation counts and actual sampling coverage are checked. Each dataset exports withheld/added/original/photo PSNR and SSIM, a full balanced video, and three matched six-second clips: GNT / uniform dense / balanced 90/10. Teacher agreement is not photographic truth.

Run `scripts/run_gnt_balanced_all.ps1` to start or resume. Artifacts are under `%USERPROFILE%/sfm_reconstruction_artifacts/gnt_finalization`: `balanced_rollout/<dataset>` for plans/models and `assets/balanced_rollout/<dataset>` for teachers, comparisons and videos. Progress is `balanced_rollout/job.json`; stage logs are in `balanced_rollout/logs`. The page updates after each dataset finishes. The GPU is used serially; unrelated Docker services are not touched. Prevent sleep and leave Docker Desktop running during the job.

Teacher frames save after each view. Completed fits are reused; incomplete fresh fits resume saved checkpoints, while an interrupted 2k continuation restarts from its pinned 10k source. Full-video raw streams record progress every 120 frames, allowing uncommitted tails to be regenerated. The host encodes each completed raw stream, verifies duration/dimensions/decoding and three decoded frame comparisons, then removes only that verified generated raw file to limit disk usage. Final browser QA checks all 16 videos, HTTP range access and synchronized three-panel controls.

ETA before starting: approximately 14–16 hours on the measured RTX 2080 setup. Most time is new GNT teacher generation, about 65–68 seconds per native image. Reused sparse-aligned dense poses reduce this slightly; concurrent host/GPU workloads can increase it. The result is resumable and quality remains unvalidated on the objects until review.
